1. ERRORE BLOCCANTE GIÀ RISCONTRATO
   ==================================================

PROBLEMA:

L’utilizzatore inserisce correttamente la password del gruppo e l’interfaccia lo considera collegato, ma quando prova a pubblicare riceve un errore.

CAUSA TECNICA DA CONTROLLARE:

Nel frontend la pubblicazione viene resa disponibile quando esiste:

* una sessione personale; oppure
* la password del gruppo.

L’API server di creazione dei post, invece, accetta soltanto una sessione personale valida.

La password del gruppo inviata senza sessione personale viene ignorata dall’endpoint di pubblicazione.

Questo crea la seguente contraddizione:

* l’interfaccia mostra che l’utente può pubblicare;
* il server rifiuta la pubblicazione;
* l’utilizzatore riceve un errore anche se ha inserito la password corretta.

CORREZIONE OBBLIGATORIA:

[ ] Stabilire in modo definitivo chi può pubblicare.

[ ] Se la password del gruppo deve permettere la pubblicazione, creare una sessione Ospite/Familiare valida e controllata.

[ ] Se la pubblicazione richiede obbligatoriamente un profilo personale, non mostrare il compositore finché il dispositivo non è associato a un profilo.

[ ] Non mostrare mai il pulsante “Pubblica” come utilizzabile se il server rifiuterà l’operazione.

[ ] Non consentire alla password comune di impersonare un Viaggiatore esistente.

[ ] Associare ogni pubblicazione a un’identità certa.

[ ] Mostrare un messaggio preciso: “Per pubblicare devi prima collegare questo dispositivo al tuo profilo”.

[ ] Non mostrare un generico “Errore”.

TEST OBBLIGATORIO DELLA CORREZIONE:

[ ] Inserire la password corretta.

[ ] Aprire Pubblica.

[ ] Pubblicare solo testo.

[ ] Pubblicare una fotografia.

[ ] Pubblicare un video.

[ ] Pubblicare un audio.

[ ] Pubblicare dieci allegati.

[ ] Verificare risposta HTTP 201.

[ ] Verificare inserimento nel database.

[ ] Verificare autore corretto.

[ ] Verificare profile_id o guest_id corretto.

[ ] Verificare comparsa immediata nel feed.

[ ] Verificare comparsa sul secondo telefono.

[ ] Verificare ricezione della notifica.

[ ] Verificare assenza di duplicazioni.

2. RUOLI DA COLLAUDARE SEPARATAMENTE
====================================

Devono essere preparati almeno i seguenti utenti:

UTENTE A – PUBBLICO SENZA PASSWORD

Può:

* vedere i contenuti pubblici;
* vedere l’itinerario pubblico;
* vedere le mappe pubbliche;
* eventualmente commentare e reagire come Familiare, se previsto.

Non può:

* pubblicare contenuti riservati;
* vedere documenti;
* vedere posizioni;
* modificare profili;
* creare inviti;
* diventare Coordinatore;
* eliminare contenuti altrui.

UTENTE B – FAMILIARE/OSPITE CON PASSWORD DI GRUPPO

Deve essere stabilito chiaramente se può:

* commentare;
* reagire;
* pubblicare post;
* pubblicare fotografie;
* pubblicare video;
* pubblicare audio.

Se può pubblicare:

[ ] deve ricevere una sessione Ospite sicura;

[ ] deve avere un nome verificabile;

[ ] non deve poter scegliere il profilo di un Viaggiatore;

[ ] non deve vedere documenti;

[ ] non deve vedere posizioni, salvo autorizzazione esplicita;

[ ] non deve accedere alle funzioni del Coordinatore.

UTENTE C – VIAGGIATORE CON SESSIONE PERSONALE

Può:

* pubblicare;
* commentare;
* reagire;
* modificare il proprio profilo;
* vedere e gestire i propri documenti;
* condividere e cancellare la propria posizione.

Non può:

* modificare profili altrui;
* vedere documenti altrui;
* modificare ruoli;
* creare inviti, salvo diversa decisione;
* eliminare post altrui;
* modificare posizioni altrui.

UTENTE D – COORDINATORE

Può:

* gestire i profili;
* creare inviti personali;
* visualizzare la situazione documentale del gruppo;
* aprire i documenti autorizzati;
* moderare i contenuti;
* revocare dispositivi;
* controllare le posizioni autorizzate.

UTENTE E – PASSWORD ERRATA

Non deve:

* ottenere accesso;
* vedere funzioni riservate;
* ricevere una sessione;
* vedere documenti;
* pubblicare;
* modificare dati.

UTENTE F – SESSIONE SCADUTA O REVOCATA

Non deve:

* continuare a pubblicare;
* aprire documenti;
* condividere posizioni;
* modificare profili;
* utilizzare privilegi precedenti.

L’applicazione deve essere utilizzata realmente, pulsante per pulsante, da almeno:

* una persona senza password;
* un Familiare con password;
* due Viaggiatori differenti;
* un Coordinatore;
* un utilizzatore non esperto;
* due telefoni contemporaneamente.

La funzione Pubblica deve essere provata realmente in tutte le condizioni previste.

Non deve essere dichiarata funzionante soltanto perché il compositore si apre.

* viene accettato dal server;
* viene registrato nel database;
* appare nel feed;
* appare sul secondo dispositivo;
* genera la notifica corretta;
* rimane disponibile dopo chiusura e riapertura;
* non viene duplicato;
* è associato all’autore corretto.
